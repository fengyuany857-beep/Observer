======================================================================
0. READ THIS FIRST
======================================================================

This file is the V1 implementation handoff for the GPT Local Guard iOS Observer motion system.
It is deliberately NOT a generic animation mood board. It defines what is allowed to move, why it moves, how it stops, what it means, how it degrades under accessibility/power constraints, and how the motion layer is prevented from becoming a second truth engine.

The visual direction is:

    Apple-native interaction shell
    x WALLHACK-like information grammar
    x Observer authoritative execution state
    x quiet motion, meaningful motion, edge-attached signal

The core aesthetic is NOT:
- cyberpunk HUD
- hacker terminal cosplay
- neon gradients
- particle backgrounds
- card rain
- every icon bouncing forever
- animated decoration pretending to be system state

The core aesthetic IS:
- Neutral Grotesk / SF system typography
- extreme scale gap (XXL -> M -> XS)
- Edge Logic
- Local Grid
- Quiet Field + Dense Node
- Archive / Metadata grammar
- restrained Functional Signal
- motion derived from real state/event changes
- large areas that are intentionally still

The most important invariant:

    MOTION IS A PROJECTION OF TRUTH.
    MOTION IS NEVER A SOURCE OF TRUTH.

If the authoritative Observer state says OFFLINE while the last known execution state was RUNNING, motion may represent the connection transition to OFFLINE, but it may NOT mutate RUNNING into FAILED.
If RuntimeHealth is STALE, the UI must not manufacture an artificial heartbeat to make the app feel alive.
If PresentationStatus is UNKNOWN after engineering completion, the UI must not animate it as a warning or failure.

2. SOURCE BASIS
======================================================================

2.1 User project truth
The motion layer preserves the frozen Observer state model:

ExecutionStatus:
PENDING / STARTING / RUNNING / WAITING_APPROVAL / VERIFYING / FINALIZING /
COMPLETED / FAILED / ABORTED / RESUMABLE / UNKNOWN

RuntimeHealth:
ACTIVE / SLOW / STALE / SUSPECTED_STUCK / UNKNOWN

ConnectionState:
CONNECTING / ONLINE / RECONNECTING / OFFLINE / SERVER_UNREACHABLE / AUTH_FAILED

ArtifactStatus:
NOT_STARTED / CREATING / CREATED / VERIFYING / VERIFIED / EXPORTED / FAILED

PresentationStatus:
UNKNOWN / CONFIRMED_PRESENTED

Truth invariants carried into motion:
- Offline != Run Failed
- Stale != Failed
- Suspected Stuck != Dead
- Completed != Presentation Confirmed
- COMPLETED + Artifact VERIFIED + Presentation UNKNOWN is a valid engineering-complete state
- Presentation UNKNOWN is neutral uncertainty, not automatic warning
- motion cannot infer completion
- frontend cannot infer missing backend truth

2.2 WALLHACK-like visual source
Applied visual grammar from the user's Drive reference system:
- ordinary high-quality grotesk typography
- extreme scale gap
- Edge Alignment over decorative centering
- Local Grid
- Quiet Field + Dense Node
- meaningful metadata
- Visible / Latent information hierarchy
- Functional Signal must have a real function and host
- avoid rounded SaaS card rain and cyber HUD
- color is not the identity; Scale / Edge / Grid / Density are the identity
- no fake codes, fake telemetry, decorative crosshairs, barcode noise, or meaningless technical garnish

For Web/Digital, the most relevant archetypes are:
- T4 QUIET FIELD + DENSE NODE
- T6 ARCHIVE INDEX
- T7 SPLIT SCALE

2.3 Current platform/library evidence reviewed during design
Apple platform findings:
- Native SwiftUI / SF Symbols are the V1 baseline.
- SF Symbols state effects and content transitions are appropriate for semantic icon transitions.
- numericText is appropriate for changing numeric metadata.
- Draw On / Draw Off is treated as an iOS 27 enhancement, NOT a V1 baseline dependency.
- Reduce Motion and animated-image accessibility preferences must be respected.
- Live Activity animation is system-managed and must not reuse arbitrary foreground looping animation logic.
- Always-On / reduced-luminance surfaces must be treated as constrained-motion contexts.

Third-party findings:
- Rive is kept behind an optional BrandMotionAdapter seam and may never own execution truth.
- RiveViewModel lifetime must be SwiftUI-stable; the simulated adapter uses @StateObject.
- Lottie is allowed only as optional local one-shot brand motion, never as the execution-state engine.
- Third-party animation assets are local-only in this V1 plan; no runtime remote animation fetching is required.
- Pow is intentionally NOT part of the V1 dependency set because the native baseline is sufficient.

======================================================================
3. MOTION PHILOSOPHY
======================================================================

3.1 The stillness budget
Approximately 90% of the interface should be still at any given moment.
Stillness is not a missing feature. It is part of the WALLHACK-like hierarchy.

3.2 Motion hierarchy
Tier 0 - STILL
Default state. Most UI does not move.

Tier 1 - DATA MOTION
Highest-value motion:
- numericText
- test count changes
- stage numbers
- elapsed time presentation where appropriate
- real heartbeat event tick
- event insertion

Tier 2 - SYMBOL MOTION
Triggered only by semantic state changes or direct interaction:
- replace symbol
- one-shot pulse
- variable color
- controlled rotate during real in-progress operations
- iOS 27 Draw enhancement

Tier 3 - STRUCTURAL MOTION
Used sparingly:
- verification sweep
- archive insertion
- native navigation continuity
Never use structural motion merely to make the page feel busy.

Tier 4 - BRAND MOTION
At most one or two hero assets in V1.
Rive may be used here later, behind a replaceable adapter.

3.3 Motion must answer a question
Every animation must be able to answer:
- What real event/state caused this?
- What information does the motion communicate?
- When does it stop?
- What does the user see with Reduce Motion enabled?
- What happens in Low Power Mode?
- What happens when the scene is inactive?
- What happens on Live Activity / Widget surfaces?

If those questions cannot be answered, the motion is decorative and should be removed.

======================================================================
4. MOTION TOKENS V1
======================================================================

Token                     Duration          Use
---------------------------------------------------------------------
SIGNAL                     140 ms            heartbeat/edge tick
MICRO                      180 ms            numeric/archive micro change
STATE                      260 ms            state transition / symbol replace
STRUCTURAL                 340 ms            verification sweep / larger change
BRAND                      420 ms            one-shot hero brand transition
INDEFINITE CYCLE           1800 ms           only real ongoing work, foreground
MAX DISCRETE               500 ms            hard upper guard for ordinary UI

Rules:
- no ordinary discrete UI transition should exceed MAX DISCRETE without explicit design review
- indefinite animation must have a real in-progress owner state
- indefinite animation must stop when the owner state ends
- indefinite animation is suppressed on constrained surfaces
- Low Power Mode suppresses unnecessary indefinite motion
- Reduce Motion eliminates spatial/looping motion and preserves the information change with fade/static alternatives

5. STATUS -> ICON -> MOTION CONTRACT
======================================================================

5.1 ExecutionStatus

PENDING
Icon: clock
Default motion: none
Reason: waiting is a state, not an activity that should pretend to be working.

STARTING
Icon: play.circle
Entry motion: one-shot pulse, STATE 260 ms
Loop: no
Reduce Motion: small fade

RUNNING
Icon: play.fill
Entry motion: symbol replace, STATE 260 ms
Continuous motion: none by default
Heartbeat: real heartbeat events generate a separate EDGE SIGNAL TICK
Critical rule: do not loop the RUNNING icon just to make the app look alive.

WAITING_APPROVAL
Icon: hand.raised.fill
Entry motion: symbol replace, STATE 260 ms
Loop: no
Critical rule: WAITING_APPROVAL is not FAILED and must not use failure motion.
Observer v1 remains read-only.

VERIFYING
Icon: checkmark.shield
V1 baseline: verificationSweep, STRUCTURAL 340 ms, one-shot on real transition
Optional iOS 27 enhancement: drawOn27
Loop: no
Reduce Motion: fade/static state change
Critical rule: iOS 27 Draw is enhancement-only, not a deployment requirement.

FINALIZING
Icon: arrow.clockwise
Foreground normal: restrained indefinite rotate, 1800 ms cycle
Low Power Mode: one-shot replace instead
Scene inactive / Live Activity / Widget: no indefinite loop
Owner condition: execution must actually be FINALIZING

COMPLETED
Icon: checkmark.circle.fill
Entry motion: symbol replace, STATE 260 ms
Loop: no
After entry: static
Critical rule: Completed does not imply Presentation CONFIRMED_PRESENTED.

FAILED
Icon: xmark.octagon.fill
Entry motion: one-shot pulse, STATE 260 ms
Loop: no
Do not add endless shake, red glow, or repeated haptics.

ABORTED
Icon: stop.circle.fill
Entry motion: symbol replace
Loop: no

RESUMABLE
Icon: arrow.clockwise.circle
Entry motion: symbol replace
Loop: no
Observer v1 must not turn this into a retry button.

UNKNOWN
Icon: questionmark.circle
Default motion: none
Do not animate unknown state as an alert unless a separate authoritative error exists.

5.2 RuntimeHealth

ACTIVE
Motion on transition to ACTIVE: small fade
No perpetual pulse.

SLOW
Motion: one-shot restrained pulse
Meaning: degraded freshness/performance, not failure.

STALE
Motion: NONE
This is deliberate. The absence of fresh motion is semantically aligned with stale data.
Do not generate fake heartbeat animation.

SUSPECTED_STUCK
Motion: one threshold-crossing edge signal tick
No forever flashing.
Text/icon remains the primary semantic carrier.

UNKNOWN
Motion: none

5.3 ConnectionState

CONNECTING
Icon: antenna.radiowaves.left.and.right
Foreground + normal power: restrained indefinite rotation if the selected symbol/rendering supports it
Low Power: one-shot pulse/replace

ONLINE
Icon: wifi
Motion: one-shot replace on restoration

RECONNECTING
Icon: arrow.clockwise
Foreground + normal power: restrained indefinite rotation
Low Power / inactive: static or one-shot fallback

OFFLINE
Icon: wifi.slash
Motion: one-shot replace/fade
Critical rule: preserve last-known execution state separately.

SERVER_UNREACHABLE
Icon: exclamationmark.triangle.fill
Motion: one-shot pulse/fade only

AUTH_FAILED
Icon: lock.slash
Motion: one-shot replace/fade only

5.4 ArtifactStatus

NOT_STARTED
Motion: none

CREATING
Motion: one-shot replace at entry; progress motion only if backed by real data

CREATED
Motion: replace

VERIFYING
Motion: verification sweep or iOS 27 Draw enhancement

VERIFIED
Motion: replace into verified symbol

EXPORTED
Motion: replace/fade

FAILED
Motion: one-shot pulse

5.5 PresentationStatus

UNKNOWN
Motion: NONE
Tone: neutral
Example copy:
  FINAL REPLY PRESENTATION / UNKNOWN
Do not render yellow/red by default.

CONFIRMED_PRESENTED
Motion: small replace/fade once

6. REAL-EVENT MOTION CONTRACT
======================================================================

HeartbeatReceived
-> edgeSignalTick
-> 140 ms
-> event-driven only
-> no autonomous timer pretending to be heartbeat

NumericMetadataChanged / TestProgressChanged
-> numericText
-> 180 ms
-> attach an explicit animation transaction; contentTransition alone is not relied on to animate async changes

StageAdvanced
-> symbol replace / state transition
-> 260 ms

EventInserted
-> archiveInsert
-> 180 ms
-> preserve list position logic; do not yank scroll position while user is inspecting history

RuntimeHealthChanged to STALE
-> no motion

RuntimeHealthChanged to SUSPECTED_STUCK
-> single edge signal threshold event
-> then static suspected-stuck state

======================================================================
7. WALLHACK-LIKE UI MOTION LANGUAGE
======================================================================

7.1 Edge Signal Rail
A 1-2 px edge-attached line can brighten briefly on a real heartbeat/status event.
It must be attached to an actual UI edge/local grid.
It is NOT a neon border.
It does not loop.
It does not become the only way to read status.

7.2 Verification Sweep
A 1 px rule grows from the leading edge once when entering VERIFYING.
It should feel like registration/inspection, not scanner-HUD cosplay.
No repeated sweep unless a new real verification phase event occurs.

7.3 Archive insertion
Timeline/event rows may use a small opacity/position insertion transition.
The event content and timestamp remain the primary signal.
Do not animate every heartbeat as a separate card.

7.4 XXL -> M -> XS motion hierarchy
The huge status word is generally stable.
Small metadata may change more often.
This creates the intended visual behavior:

    RUNNING

    STAGE 04 / 07
    BUILD / 00:18:42
    LAST HEARTBEAT / 2s

The interface feels alive because real metadata changes, not because the hero word bounces.

7.5 Functional color
The V1 code includes a project-specific signal accent placeholder.
It is NOT claimed to be an official WALLHACK brand color.
Semantic system status must remain icon + text + appropriate semantic color, never color-only.

7.6 Prohibited motion motifs
- infinite breathing glow everywhere
- random pulse on cards
- particle background
- Matrix/code rain
- global scanlines
- neon border loops
- RGB/gradient animation
- spring/bounce on every symbol
- endless shake on error
- 3D tilt cards
- magnetic buttons everywhere
- repeated shimmer on static content
- fake heartbeat timer
- state changes inferred from animation completion
- full-screen cyber HUD transitions

======================================================================
8. ACCESSIBILITY / POWER / VISIBILITY
======================================================================

Accessibility rules:
- respect Reduce Motion
- respect the system preference controlling animated images for third-party animated assets
- icon + text is always the primary semantic channel
- color is supplemental
- motion is supplemental
- transitions must not hide state labels from VoiceOver semantics

Reduce Motion fallback:
- loops -> none
- spatial sweep -> small fade/static
- symbol replace -> opacity/cross-fade style behavior
- numeric change -> reduced movement / opacity where needed
- third-party brand animation -> static/final frame

Power/visibility:
- inactive scene suppresses indefinite motion
- Low Power Mode suppresses nonessential indefinite animation
- reduced luminance / Always-On contexts are treated as constrained
- no background timer exists solely to feed decoration

Haptics V1:
- no automatic haptic for background state changes in this simulated system
- do not vibrate on every heartbeat/test/event
- if later added, haptics must be user-initiated or attached to truly high-value foreground feedback and pass a separate UX/accessibility review

======================================================================
9. LIVE ACTIVITY / WIDGET BOUNDARY
======================================================================

Live Activity is NOT the same motion environment as the foreground app.

Rules:
- no Rive
- no Lottie
- no arbitrary indefinite foreground loops
- rely on system-managed state transitions
- use text/symbol change and numeric transitions only where appropriate
- keep payload glanceable and privacy-safe
- status/stage/progress/health/last update only
- no logs, command arguments, secrets, full paths

Widget rules:
- treat the widget as a snapshot, not a high-frequency truth surface
- default static
- Last Run / Status / Stage / Health / Last Updated
- no fake realtime animation

15. ^10 AUDIT HISTORY AND FINAL CLEAN STREAK
======================================================================

Important audit behavior:
Several real findings were discovered during the audit. Each material finding was fixed in the simulated source and reset the ^10 clean streak rather than being counted as a clean pass.

Material findings discovered and repaired before final convergence:

F-01 iOS availability mismatch
Finding:
Draw On / Draw Off cannot be treated as the iOS 26 baseline.
Repair:
Draw is capability-gated as an iOS 27 enhancement. V1 baseline uses verificationSweep/replace/fade paths.

F-02 Rive SwiftUI lifecycle risk
Finding:
A Rive model recreated as an ordinary value property can break lifecycle/state behavior under SwiftUI re-rendering.
Repair:
Simulated adapter owns RiveViewModel with @StateObject and keeps the runtime behind BrandMotionAdapter.

F-03 Native symbol-effect target error
Finding:
A prior simulated brand glyph attempted symbol-style behavior on a non-symbol shape.
Repair:
Changed animated primitive to an SF Symbol image.

F-04 Accessibility was only policy-level
Finding:
A renderer could still animate if passed a stale/wrong MotionCommand after accessibility preferences changed.
Repair:
Added renderer-level defense-in-depth checks for Reduce Motion / scene activity.

F-05 contentTransition transaction gap
Finding:
Declaring a content transition is not enough to guarantee an async value change is actually animated.
Repair:
Numeric and replace renderers attach explicit, controlled animation transactions.

F-06 protocol/provider revision drift during the task
Finding:
GP-001 / GP-003 / SC-001 / UPO Manifest provider revisions changed after the first audit pass.
Repair:
Formal baseline was re-read. Current semantic routing remained compatible, UPO remained R8, and the ^10 clean streak was reset to zero. The ten audit rounds below were rerun under the revalidated baseline.

public enum ObserverMotionPolicy {
    /// Motion never creates truth. It only reflects already-authoritative state/event changes.
    public static func resolve(trigger: MotionTrigger, env: MotionEnvironment) -> MotionCommand {
        // Widget / Always-On / inactive surfaces: keep movement extremely conservative.
        if env.luminanceReduced || !env.sceneActive {
            return fallbackForConstrainedSurface(trigger)
        }

        // Reduce Motion: preserve information change but eliminate spatial/looping motion.
        if env.reduceMotion {
            return reducedMotion(trigger)
        }

        switch env.surface {
        case .widget:
            return widgetMotion(trigger)
        case .liveActivity:
            return liveActivityMotion(trigger)
        case .appForeground:
            return appMotion(trigger, env: env)
        }
    }

    private static func appMotion(_ trigger: MotionTrigger, env: MotionEnvironment) -> MotionCommand {
        switch trigger {
        case .initialRender:
            return .none

        case .heartbeatReceived:
            // Crucial WALLHACK rule: animate the *real heartbeat event*, never a fake autonomous heartbeat loop.
            return MotionCommand(kind: .edgeSignalTick, durationMS: ObserverMotionTokens.signalMS, intensity: 0.65, reason: "Real heartbeat event")

        case .numericMetadataChanged, .testProgressChanged:
            return MotionCommand(kind: .numericText, durationMS: ObserverMotionTokens.microMS, intensity: 0.75, reason: "Meaningful metadata changed")

        case .stageAdvanced:
            return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.85, reason: "Stage boundary changed")

        case .eventInserted:
            return MotionCommand(kind: .archiveInsert, durationMS: ObserverMotionTokens.microMS, intensity: 0.65, reason: "New forensic event appended")

        case .runtimeHealthChanged(_, let to):
            switch to {
            case .active:
                return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.microMS, intensity: 0.5, reason: "Health returned active")
            case .slow:
                return MotionCommand(kind: .pulseOnce, durationMS: ObserverMotionTokens.stateMS, intensity: 0.55, reason: "Health degraded to slow")
            case .stale:
                // Absence of motion is semantically useful: stale means the stream stopped refreshing.
                return .none
            case .suspectedStuck:
                return MotionCommand(kind: .edgeSignalTick, durationMS: ObserverMotionTokens.stateMS, intensity: 1.0, reason: "Threshold crossing: suspected stuck")
            case .unknown:
                return .none
            }

        case .executionChanged(_, let to):
            switch to {
            case .starting:
                return MotionCommand(kind: .pulseOnce, durationMS: ObserverMotionTokens.stateMS, intensity: 0.65, reason: "Execution entered starting")
            case .running:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.65, reason: "Execution entered running")
            case .waitingApproval:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.75, reason: "Execution is waiting for approval")
            case .verifying:
                if env.supportsDrawEffects27 {
                    return MotionCommand(kind: .drawOn27, durationMS: ObserverMotionTokens.structuralMS, intensity: 0.8, reason: "iOS 27 enhancement for verification")
                }
                return MotionCommand(kind: .verificationSweep, durationMS: ObserverMotionTokens.structuralMS, intensity: 0.7, reason: "Verification entered; iOS 26-compatible baseline")
            case .finalizing:
                if env.lowPowerMode {
                    return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.6, reason: "Low Power Mode suppresses indefinite rotation")
                }
                return MotionCommand(kind: .rotateIndefinite, durationMS: ObserverMotionTokens.indefiniteCycleMS, loops: true, intensity: 0.45, reason: "Finalization active and foreground-visible")
            case .completed:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.7, reason: "Execution completed")
            case .failed:
                return MotionCommand(kind: .pulseOnce, durationMS: ObserverMotionTokens.stateMS, intensity: 0.85, reason: "Execution failed")
            case .aborted:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.65, reason: "Execution aborted")
            case .resumable:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.65, reason: "Execution can resume")
            case .pending, .unknown:
                return .none
            }

        case .connectionChanged(_, let to):
            switch to {
            case .connecting, .reconnecting:
                if env.lowPowerMode {
                    return MotionCommand(kind: .pulseOnce, durationMS: ObserverMotionTokens.stateMS, intensity: 0.5, reason: "Connection activity; low-power fallback")
                }
                return MotionCommand(kind: .rotateIndefinite, durationMS: ObserverMotionTokens.indefiniteCycleMS, loops: true, intensity: 0.4, reason: "Connection work is actively in progress")
            case .online:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.6, reason: "Connection restored")
            case .offline, .serverUnreachable, .authFailed:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.7, reason: "Connection entered terminal/degraded state")
            }

        case .artifactChanged(_, let to):
            switch to {
            case .creating:
                return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.microMS, intensity: 0.5, reason: "Artifact creation began; no fake progress")
            case .verifying:
                return MotionCommand(kind: .verificationSweep, durationMS: ObserverMotionTokens.structuralMS, intensity: 0.7, reason: "Artifact verification event")
            case .verified, .exported:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.65, reason: "Artifact reached verified/exported state")
            case .failed:
                return MotionCommand(kind: .pulseOnce, durationMS: ObserverMotionTokens.stateMS, intensity: 0.8, reason: "Artifact failed")
            case .notStarted, .created:
                return .none
            }

        case .presentationChanged(_, let to):
            // Presentation UNKNOWN is explicitly neutral and must not animate like a warning.
            switch to {
            case .unknown:
                return .none
            case .confirmedPresented:
                return MotionCommand(kind: .replaceSymbol, durationMS: ObserverMotionTokens.stateMS, intensity: 0.55, reason: "Presentation confirmation observed")
            }
        }
    }

    private static func reducedMotion(_ trigger: MotionTrigger) -> MotionCommand {
        switch trigger {
        case .numericMetadataChanged, .testProgressChanged:
            return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.signalMS, intensity: 0.35, reason: "Reduce Motion: preserve content update without spatial movement")
        case .executionChanged, .connectionChanged, .runtimeHealthChanged, .artifactChanged, .presentationChanged, .stageAdvanced:
            return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.microMS, intensity: 0.35, reason: "Reduce Motion: cross-fade semantic state change")
        case .heartbeatReceived, .eventInserted, .initialRender:
            return .none
        }
    }

    private static func widgetMotion(_ trigger: MotionTrigger) -> MotionCommand {
        switch trigger {
        case .numericMetadataChanged, .testProgressChanged:
            return MotionCommand(kind: .numericText, durationMS: ObserverMotionTokens.microMS, intensity: 0.45, reason: "Widget numeric update")
        default:
            return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.microMS, intensity: 0.3, reason: "Widget uses glanceable low-motion transition")
        }
    }

    private static func liveActivityMotion(_ trigger: MotionTrigger) -> MotionCommand {
        // This is a policy abstraction only. The real Live Activity renderer must use system-supported transitions;
        // it must not assume app-level Animation modifiers or third-party animation runtimes are honored.
        switch trigger {
        case .numericMetadataChanged, .testProgressChanged:
            return MotionCommand(kind: .numericText, durationMS: ObserverMotionTokens.microMS, intensity: 0.45, reason: "Live Activity numeric content transition")
        default:
            return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.microMS, intensity: 0.3, reason: "Live Activity system-managed content transition")
        }
    }

    private static func fallbackForConstrainedSurface(_ trigger: MotionTrigger) -> MotionCommand {
        switch trigger {
        case .numericMetadataChanged, .testProgressChanged:
            return MotionCommand(kind: .fade, durationMS: ObserverMotionTokens.signalMS, intensity: 0.25, reason: "Constrained surface: no continuous animation")
        default:
            return .none
        }
    }
}

public enum ObserverMotionInvariants {
    /// Static policy checks used by tests and audit tools.
    public static func violations(for command: MotionCommand, env: MotionEnvironment) -> [String] {
        var out: [String] = []
        if command.durationMS < 0 { out.append("NEGATIVE_DURATION") }
        if !command.loops && command.durationMS > ObserverMotionTokens.maxDiscreteMS { out.append("DISCRETE_TOO_LONG") }
        if env.reduceMotion && command.loops { out.append("LOOP_UNDER_REDUCE_MOTION") }
        if (!env.sceneActive || env.luminanceReduced) && command.loops { out.append("LOOP_ON_CONSTRAINED_SURFACE") }
        if env.surface != .appForeground && command.kind == .drawOn27 { out.append("DRAW27_OUTSIDE_APP") }
        if command.kind == .drawOn27 && !env.supportsDrawEffects27 { out.append("DRAW27_WITHOUT_CAPABILITY") }
        return out
    }
}

    public let command: MotionCommand
    public let changeToken: Int

    @Environment(\.scenePhase) private var scenePhase

        switch command.kind {

                    .symbolEffect(.pulse, value: changeToken)

                .symbolRenderingMode(.monochrome)
                .symbolEffect(.rotate, isActive: active)

        case .variableColor:
            Image(systemName: systemName)
                .symbolRenderingMode(.hierarchical)
                .symbolEffect(.variableColor.iterative, isActive: active)

        case .replaceSymbol:
            Image(systemName: systemName)
                .symbolRenderingMode(.monochrome)
                .contentTransition(reduceMotion ? .opacity : .symbolEffect(.replace.offUp))
                .animation(reduceMotion ? nil : .timingCurve(0.22, 1, 0.36, 1, duration: 0.26), value: systemName)

        case .drawOn27:
            drawOn27(active: active)

        default:
            Image(systemName: systemName)
                .symbolRenderingMode(.monochrome)
        }
    }

    @ViewBuilder

        if #available(iOS 27.0, *) {
            Image(systemName: systemName)
                .symbolRenderingMode(.monochrome)
                .symbolEffect(.drawOn.wholeSymbol, isActive: active)
        } else {
            Image(systemName: systemName)
                .symbolRenderingMode(.monochrome)
                .contentTransition(.symbolEffect(.replace.offUp))
        }
    }
}

import Foundation

@main
struct ObserverMotionCoreTests {
    static var failures = 0
    static var checks = 0

    static func expect(_ condition: @autoclosure () -> Bool, _ message: String) {
        checks += 1
        if !condition() {
            failures += 1
            print("FAIL: \(message)")
        }
    }

    static func main() {
        let normal = MotionEnvironment(surface: .appForeground)
        let rm = MotionEnvironment(surface: .appForeground, reduceMotion: true)
        let lowPower = MotionEnvironment(surface: .appForeground, lowPowerMode: true)
        let inactive = MotionEnvironment(surface: .appForeground, sceneActive: false)
        let live = MotionEnvironment(surface: .liveActivity)
        let widget = MotionEnvironment(surface: .widget)
        let ios27 = MotionEnvironment(surface: .appForeground, supportsDrawEffects27: true)

        let heartbeat = ObserverMotionPolicy.resolve(trigger: .heartbeatReceived, env: normal)
        expect(heartbeat.kind == .edgeSignalTick, "Heartbeat should produce event-driven edge tick")
        expect(heartbeat.loops == false, "Heartbeat must not create synthetic loop")

        let stale = ObserverMotionPolicy.resolve(trigger: .runtimeHealthChanged(from: .active, to: .stale), env: normal)
        expect(stale.kind == .none, "STALE should communicate absence of refresh, not fake motion")

        let stuck = ObserverMotionPolicy.resolve(trigger: .runtimeHealthChanged(from: .stale, to: .suspectedStuck), env: normal)
        expect(stuck.kind == .edgeSignalTick, "SUSPECTED_STUCK should get threshold-crossing signal")
        expect(stuck.loops == false, "SUSPECTED_STUCK signal must not loop forever")

        let finalizing = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .verifying, to: .finalizing), env: normal)
        expect(finalizing.kind == .rotateIndefinite && finalizing.loops, "FINALIZING can loop only while actively working")

        let finalizingLP = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .verifying, to: .finalizing), env: lowPower)
        expect(finalizingLP.loops == false, "Low Power Mode should suppress indefinite rotation")

        let verify26 = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .running, to: .verifying), env: normal)
        expect(verify26.kind == .verificationSweep, "iOS 26 baseline must not require Draw")

        let verify27 = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .running, to: .verifying), env: ios27)
        expect(verify27.kind == .drawOn27, "iOS 27 may use Draw enhancement")

        let complete = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .finalizing, to: .completed), env: normal)
        expect(complete.kind == .replaceSymbol && !complete.loops, "COMPLETED should settle after one transition")

        let presentationUnknown = ObserverMotionPolicy.resolve(trigger: .presentationChanged(from: .confirmedPresented, to: .unknown), env: normal)
        expect(presentationUnknown.kind == .none, "Presentation UNKNOWN must stay neutral, not warning-animated")

        let numeric = ObserverMotionPolicy.resolve(trigger: .numericMetadataChanged, env: normal)
        expect(numeric.kind == .numericText, "Metadata numbers should use numeric transition")

        let rmFinal = ObserverMotionPolicy.resolve(trigger: .executionChanged(from: .verifying, to: .finalizing), env: rm)
        expect(rmFinal.kind == .fade && !rmFinal.loops, "Reduce Motion must convert state movement to fade")

        let inactiveReconnect = ObserverMotionPolicy.resolve(trigger: .connectionChanged(from: .offline, to: .reconnecting), env: inactive)

            .artifactChanged(from: .notStarted, to: .creating),

            .artifactChanged(from: .created, to: .verifying),
            .artifactChanged(from: .verifying, to: .verified),
            .artifactChanged(from: .verified, to: .exported),
            .artifactChanged(from: .creating, to: .failed),
            .presentationChanged(from: .unknown, to: .confirmedPresented)
        ]
        for trigger in exhaustiveTriggers {
            expect(!ObserverMotionPolicy.resolve(trigger: trigger, env: rm).loops, "Reduce Motion must never loop")
            expect(!ObserverMotionPolicy.resolve(trigger: trigger, env: live).loops, "Live Activity policy must never loop")
            expect(!ObserverMotionPolicy.resolve(trigger: trigger, env: widget).loops, "Widget policy must never loop")
